# Use Case: Onboard Project

Scan a project, profile its purpose and architecture, and register it in the architect portfolio.

## Input
- Target project path
- Organization name (optional, auto-detected from path)
- Rescan flag (optional, refreshes existing profile)

## Output
- ScoutReport (see `domain/entities.md` → ScoutReport)
- ProjectBrief (see `domain/entities.md` → ProjectBrief)
- CLAUDE.md written to the target project root
- doc_paths array of documentation file paths found in the target project
- PortfolioEntry written to `portfolio/<org>/<project>/<component>.json`
- Registry updated in `portfolio/registry.json`

## Agent(s)
- **scout** (model: haiku) — technology detection
- **profiler** (model: sonnet) — project analysis, brief generation, CLAUDE.md generation

## Steps

1. Read `portfolio/registry.json` — check if path already exists
   - If found and no rescan: display existing profile and exit
   - If found and rescan: proceed (will update)
2. Detect organization:
   - Read all `portfolio/*/organization.json` files
   - Match by provided org name, or by path_root prefix
   - If no match: ask user to create new org or skip org association
3. Run scout agent to produce ScoutReport (see `domain/entities.md` → ScoutReport)
4. Derive project and component names from path
5. Run profiler agent to produce ProjectBrief + doc_paths + CLAUDE.md:
   - Pass project path + ScoutReport from step 3 + portfolio location (`org/project/component` from steps 2+4)
   - If no README/docs exist: profiler produces minimal brief from package manifests and directory names
   - If CLAUDE.md exists in target project: profiler reads it, asks user whether to merge/overwrite/skip
   - Write CLAUDE.md to target project root (unless user chose skip)
6. Determine recommended agents based on scout report:
   - All projects: coder, tester, reviewer, debugger, documenter, dependency-manager
   - Frontend → add coder-frontend; Backend → add coder-backend; Mobile → add coder-mobile
   - CI present → add ci-cd; Containers present → add coder-infra
7. Build PortfolioEntry (see `domain/entities.md` → PortfolioEntry)
   - Include scout_report, brief, and doc_paths
   - Include `worktree_setup` from profiler's "Worktree Setup" output (Phase 5.5) — after user verification below
   - Include `portfolio_guides` list populated in step 8
8. **Write worktree_setup and portfolio guides** (from profiler Phases 5.5 and 5.7):

   a. Present the profiler's "Worktree Setup" section to the user for verification:
      - If `copy_paths` is non-empty: confirm each detected path is correct before writing. User may remove any incorrect entries.
      - If `copy_paths` is empty with explanation ("No gitignored runtime config files detected"): no action needed — proceed with empty `copy_paths`.
      - If signing artifacts were flagged (⚠ note in output): prompt the user to manually add them to `copy_paths` if appropriate.
      Update the PortfolioEntry with the verified `worktree_setup`.

   b. Handle the profiler's "Portfolio Guides (draft)" section:
      - If content is `"none — setup complexity below threshold"`: skip this sub-step entirely. Do not prompt the user.
      - If a guide skeleton is present: present the draft to the user (user can respond "skip" to skip without writing).
        - On approval: write `portfolio/<org>/<project>/local-dev-setup.md` **first**, then add `"local-dev-setup.md"` to `portfolio_guides` in the PortfolioEntry. Write order matters: file first, JSON second. A failure between the two leaves an orphaned file (harmless) rather than a dangling JSON reference (causes load errors).
        - On "skip": do not write the file; do not update `portfolio_guides`.

   c. On `/onboard rescan` (rescan flag set): if `local-dev-setup.md` already exists in the portfolio directory, overwrite it. The file header (`<!-- auto-generated by /onboard — manual edits will be overwritten on /onboard rescan -->`) is the overwrite signal. Users who want to preserve manual edits must remove the header line.

9. Present full PortfolioEntry for user approval
10. Write component profile and update registry

## Post-conditions
- Only CLAUDE.md is written to the target project
- Portfolio entry is accessible via `usecases/load-portfolio-context.md`
- `worktree_setup` is always present in the entry (either with `copy_paths` or explicitly empty)
- `local-dev-setup.md` is written to the portfolio directory if setup complexity was detected
